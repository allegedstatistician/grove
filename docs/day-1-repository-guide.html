Interpret focused pytest output

ResultMeaning while the xfail marker exists
XFAIL (not implemented)The test reached NotImplementedError. Its assertions did not pass.
strict XPASSThe test stopped raising NotImplementedError. This is progress, though strict mode exits nonzero.
FAILEDA different exception or assertion failed. Read the innermost frame in Grove source.
[XPASS(strict)] under “FAILURES” is still progress.

It means the test body completed successfully. The reported failure is strict mode objecting that a test marked as an expected failure unexpectedly passed; it is not an assertion failure in your function.

For an ordinary red/green loop while implementing one function, disable the expected-failure wrapper temporarily:

uv run pytest tests/test_repo.py -k discover --runxfail -v

Now PASSED means the selected behavior works, and FAILED exposes the actual traceback. Remove the module-level marker only after every repository function is complete.

Mental model

Git directory ≠ working-tree root

/project/ — files you edit   ·   /project/.git/ — Git’s administrative data

A normal repository exposes both locations. pygit2 calls the metadata directory repo.path and the checkout directory repo.workdir.

QuestionCorrect sourceScratch fixture result
Where is Git’s repository data?repo.pathscratch/.git/
Where are the checked-out files?repo.workdirscratch/
Do not derive one path from the other.

Linked worktrees store their administrative directory elsewhere. Ask pygit2 for workdir instead of assuming repo.path.parent.

1

discover_repository

Contract: given a Path, search it and its parents. Return the discovered Git directory as a Path. If discovery fails, raise NotAGitRepository with the starting path in the message.

Required existing name.

Import NotAGitRepository from grove.errors. It is already part of the scaffold; do not create another class with the same name.

pygit2.discover_repository ↗ pathlib.Path ↗

The library’s important behavior

Discovery failure returns None; it does not raise. The installed type can be read as:

def discover_repository(
    path: str | Path, ...
) -> str | None: ...

A generic narrowing pattern looks like this:

found = pygit2.discover_repository(candidate)
if found is None:
    raise LookupError(candidate)
Translate, don’t copy.

The example uses LookupError only to show narrowing. Grove already has the more meaningful NotAGitRepository.

Concepts to learn

  • Optional narrowing: after is None, mypy can prove the other branch contains a string.
  • Boundary conversion: pygit2 returns a string; Grove’s public interface promises a Path.
  • Domain errors: translate a library convention into vocabulary meaningful to your application.

Scope decisions

  • Keep across_fs=False; Grove does not need cross-filesystem discovery.
  • Treat start as an existing directory for now. Do not invent nonexistent-path behavior without a test.
  • Let Path normalize a trailing separator. Do not trim path strings manually.
  • When the API returns None, there is no caught exception to chain.

Focused check

uv run pytest tests/test_repo.py -k discover -v

While the module marker remains, successful assertions appear as strict XPASS results. That is progress.

2

open_repository

Contract: reuse discovery, construct a pygit2.Repository, and reject a repository that has no working tree.

Reuse both existing errors.

Import NotAGitRepository and RepositoryIsBare from grove.errors. Let discover_repository own the first error so this function does not duplicate discovery logic.

pygit2.Repository ↗ Repository.is_bare ↗ Exception chaining ↗

The constructor relationship, stripped of Grove’s validation, is:

git_dir = pygit2.discover_repository(candidate)
opened = pygit2.Repository(git_dir)

Your actual function must narrow the nullable discovery result first. Reusing Task 1 keeps the NotAGitRepository behavior in one place.

Bare repository rule

Check the boolean is_bare property. Do not infer bareness from a directory name; a bare repository is not required to end in .git.

Catch narrowly.

Do not use except Exception. If a specific pygit2 exception has an accurate Grove equivalent, translate it with raise ... from err. Otherwise let the unexpected failure remain visible.

Test gap worth filling

The docstring promises RepositoryIsBare, but the scaffold does not test it. Add one temporary bare repository under pytest’s tmp_path and assert the named domain error.

3

repository_root

Contract: return the directory containing checked-out files, not the metadata directory.

Repository.workdir ↗ pathlib.Path ↗

workdir is typed as str | None. Normal repositories return a normalized path. Bare repositories return None.

pygit2 1.20 has conflicting type information.

The lower-level stub and runtime documentation allow None, but the public BaseRepository class annotates workdir as str. Some editors therefore claim that workdir is not None is always true. Check the separately typed repo.is_bare boolean before reading workdir; do not hide the mismatch with # type: ignore or cast().

value = object_with_optional_path.workdir
if value is None:
    raise RuntimeError("no working directory")

The example demonstrates narrowing only. Grove should use RepositoryIsBare, not a generic runtime error.

Do not use assert.

A bare repository is a possible runtime input, even if open_repository normally filters it out. It deserves a domain error that is not removed by optimized Python execution.

Focused check

uv run pytest tests/test_repo.py -k repository_root -v
4

is_dirty

Contract: report whether the index or working tree differs from HEAD under Grove’s safety policy.

Repository.status() ↗ FileStatus enum ↗ Python any() ↗

Three states, two comparisons

HEAD tree  <──── INDEX_* flags ────>  index
index      <────── WT_* flags ────>  working tree
SituationComparisonRepresentative flag
A new file was stagedindex differs from HEADINDEX_NEW
A tracked file was editedworktree differs from indexWT_MODIFIED
A tracked file was deletedworktree/index records deletionWT_DELETED or INDEX_DELETED
A new file is untrackedworktree path is absent from indexWT_NEW

Status flags are a bitmask: one path may have multiple flags simultaneously. Do not assume a value always equals exactly one nonzero member.

Read the dictionary in the correct direction

key: repository-relative file path (str)
value: one FileStatus flag or a combination of FileStatus flags

For example, one edited file and one new file may produce:

{
    "README.md": FileStatus.WT_MODIFIED,
    "notes.txt": FileStatus.WT_NEW,
}
FileStatus.CURRENT means “no change” for one path.

It is the zero-valued flag, not a collection of the repository’s current enum values. Clean paths are normally absent from status(), so a clean repository generally produces an empty dictionary.

A path can have combined index and worktree flags. Use bitwise & to ask whether one member is present:

combined = FileStatus.INDEX_MODIFIED | FileStatus.WT_MODIFIED
bool(combined & FileStatus.WT_MODIFIED)  # True

If Grove’s policy is “every change returned by the default status call is dirty,” you do not need to list every individual flag. Reason from whether the mapping contains any changed entry.

The documentation’s inspection shape is:

for filepath, flags in repo.status().items():
    if flags != FileStatus.CURRENT:
        print(filepath)

Grove needs a boolean, not printed paths. Consider what an empty status mapping means and whether at least one changed entry is enough.

Explore it in a REPL

Start the project’s Python environment:

uv run python

At the >>> prompt, enter these expressions one at a time:

from pathlib import Path
from grove.repo import open_repository
from pygit2.enums import FileStatus
repo = open_repository(Path.cwd())
status = repo.status()
status

Inspect symbolic names and underlying integers:

[(path, flags.name, flags.value) for path, flags in status.items()]

Try a combined flag without modifying files:

combined = FileStatus.INDEX_MODIFIED | FileStatus.WT_MODIFIED
bool(combined & FileStatus.WT_MODIFIED)

Use exit() or Control-D to leave. Inspecting Path.cwd() reads Grove’s own repository and does not modify it.

Practice loop

Implement narrowly, verify deliberately

  1. Implement one function.
  2. Run its focused test command.
  3. Read XPASS as progress while the module marker is present.
  4. After every Day 1 behavior works, remove the module-level xfail marker yourself.
  5. Run the whole module, then mypy, then the complete suite.

Definition of done

Review checklist

  • Public path values use pathlib.Path, not manual string manipulation.
  • Failed discovery raises NotAGitRepository.
  • A bare repository raises RepositoryIsBare.
  • No assert is used for runtime input validation.
  • No bare except, except Exception, # type: ignore, or cast() was introduced.
  • Translated library exceptions retain their cause with raise ... from err.
  • The root comes from repo.workdir, not assumptions about repo.path.
  • Dirty state includes staged and untracked content but excludes ignored content.
  • Both mypy and the complete test suite finish without unexpected failures.
